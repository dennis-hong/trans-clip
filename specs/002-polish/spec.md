# Feature Specification: 글 다듬기 (Text Polish) 기능

**Feature Branch**: `002-polish`
**Created**: 2026-01-05
**Status**: Draft
**Input**: 사용자가 빠르게 작성한 러프한 초안을 AI가 명료하고 정돈된 글로 다듬어주는 기능. Cmd+Shift+CC 단축키로 트리거.

## 개요

### 해결하려는 문제

> "내용은 다 적었는데, 정리가 안 돼서 그냥 보내기가 좀 그래..."

업무 중 슬랙 메시지, 컨플루언스 문서, 이메일 등을 작성할 때:
- **내용은 머릿속에 다 있고**, 일단 빠르게 타이핑해서 초안을 작성함
- 하지만 **정리가 안 되어** 전달력이 떨어지는 느낌
- 다듬고 싶지만 **시간이 없거나**, **글 솜씨에 자신이 없음**
- 결국 그냥 보내거나, 다듬는 데 불필요한 시간을 소비함

### 제공하는 가치

**"러프한 초안 → 깔끔하게 정돈된 글"**

- 내용은 그대로 유지하면서 **명료하고 전달이 잘 되게** 정리
- 상황(누구에게)과 채널(어디서)에 맞는 적절한 톤과 포맷 적용
- **글 솜씨가 부족한 사용자**: AI가 대신 다듬어줌
- **시간을 아끼고 싶은 사용자**: 빠르게 초안만 쓰고 다듬기는 AI에게 위임

### 핵심 차별점
- **번역**: 언어 A → 언어 B 변환
- **다듬기**: 러프한 초안 → 정돈된 완성본 (같은 언어, 같은 내용)

## User Scenarios & Testing

### User Story 1 - 러프한 초안을 깔끔하게 다듬기 (Priority: P1)

개발자 김민수는 팀장에게 프로젝트 진행 상황을 슬랙으로 보고해야 합니다.
급하게 생각나는 대로 내용을 적었지만, 정리가 안 되어 보내기가 망설여집니다.

```
원문 (러프한 초안):
"어제 리뷰 받은거 반영했고요 테스트도 다 돌렸는데 하나 실패해서 지금 보고 있어요 
오늘 중으로 될것 같은데 혹시 급하면 말씀해주세요"
```

텍스트를 드래그하고 Cmd+Shift+CC를 누릅니다.
상황: "상사에게 보고", 채널: "슬랙 메시지"를 선택합니다.

```
다듬은 결과:
"안녕하세요, 진행 상황 공유드립니다.
- 어제 리뷰 피드백 반영 완료
- 테스트 진행 중 1건 실패 → 현재 원인 분석 중
- 오늘 중 해결 예정

혹시 급하시면 말씀해주세요!"
```

마음에 들어서 복사 버튼을 누르고 슬랙에 붙여넣습니다.

**Why this priority**: 핵심 기능으로, 글 다듬는 시간을 아끼고 커뮤니케이션 품질을 높이는 주요 기능입니다.

**타겟 사용자**:
- 글 솜씨에 자신이 없어서 다듬어진 글을 원하는 사용자
- 글 다듬을 시간을 아끼고 싶은 바쁜 사용자
- 내용은 빠르게 쓰고, 정돈은 AI에게 맡기고 싶은 사용자

**Independent Test**: 텍스트 선택 후 Cmd+Shift+CC를 눌러 다듬기 팝업이 나타나고 결과가 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 러프하게 작성한 텍스트를 선택한 상태, **When** Cmd+Shift+CC를 누름, **Then** 다듬기 팝업 창이 나타나고 원문과 정돈된 결과가 표시됨
2. **Given** 다듬기 팝업이 열린 상태, **When** "복사" 버튼 클릭, **Then** 다듬어진 텍스트가 클립보드에 복사됨
3. **Given** 다듬기 팝업이 열린 상태, **When** 상황/채널 선택을 변경, **Then** 해당 설정에 맞게 다시 다듬은 결과가 표시됨
4. **Given** 다듬어진 결과가 마음에 드는 상태, **When** "바꾸기" 버튼 클릭, **Then** 원본 위치의 텍스트가 다듬어진 내용으로 대체됨

## 상황(Context) 정의

사용자가 글을 쓰는 **목적과 대상**에 따른 분류입니다.
상황에 따라 같은 내용이라도 다르게 정돈됩니다.

| Context ID | 이름 | 대상 | 다듬는 방향 |
|------------|------|------|-------------|
| `report-to-superior` | 상사에게 보고 | 상사, 임원 | 존댓말, 핵심 먼저, 결론-근거 순서, 명확한 액션 |
| `team-announcement` | 팀 공지 | 팀원들 | 친근하면서 명확, 불릿포인트로 정리, 행동 요청 명시 |
| `peer-discussion` | 동료와 논의 | 동료 | 편하게, 논의 포인트 정리, 질문 명확히 |
| `external-formal` | 외부 커뮤니케이션 | 파트너사, 고객사 | 격식체, 정중함, 배경-목적-요청 구조 |
| `documentation` | 문서 작성 | 불특정 독자 | 객관적, 3인칭, 단계별 설명, 명료함 |

### 예시: 같은 내용, 다른 상황

**원문 (러프한 초안)**:
> "API 변경해야할것 같아요 기존 방식이 느려서 새로운 방식 테스트해봤는데 훨씬 빨라요 적용해도 될까요"

**상사에게 보고**:
> "API 개선 건 보고드립니다. 기존 방식 대비 성능 이슈가 있어 새로운 방식을 테스트한 결과, 유의미한 성능 향상을 확인했습니다. 적용 진행해도 괜찮을까요?"

**동료와 논의**:
> "API 변경 건 논의하고 싶어! 기존 방식이 느려서 새로운 방식 테스트해봤는데 훨씬 빠르더라. 어떻게 생각해?"

### 사용자 정의 상황

사용자는 기본 제공되는 상황 외에 **커스텀 상황**을 추가할 수 있습니다.
- 예: "CEO에게 직접 보고", "인턴에게 설명", "면접 피드백 전달"

## 채널(Channel) 정의

사용자가 글을 작성하는 **플랫폼/매체**에 따른 분류입니다.
채널에 따라 적절한 길이와 포맷으로 정돈됩니다.

| Channel ID | 이름 | 플랫폼 | 다듬는 방향 |
|------------|------|--------|-------------|
| `slack-message` | 슬랙 메시지 | Slack DM/채널 | 짧고 간결하게, 한눈에 파악, 이모지 OK |
| `slack-thread` | 슬랙 스레드 | Slack 스레드 | 컨텍스트 유지, 약간 더 상세하게 |
| `confluence-wiki` | 컨플루언스 위키 | Confluence | 헤딩/불릿으로 구조화, 완전한 문장 |
| `jira-comment` | Jira 코멘트 | Jira 이슈 | 간결하게, 결론과 액션 중심 |
| `jira-description` | Jira 설명 | Jira 이슈 | 배경-목표-상세-AC 구조 |
| `email` | 이메일 | 업무 메일 | 인사-본문-마무리, 요청사항 명확히 |
| `pr-description` | PR 설명 | GitHub/GitLab | What-Why-How, 변경사항 요약 |
| `code-review` | 코드 리뷰 | 코드 리뷰 | 건설적으로, 구체적 제안 포함 |

### 예시: 같은 내용, 다른 채널

**원문 (러프한 초안)**:
> "로그인 버그 있어요 토큰 만료되면 리다이렉트 안되고 그냥 에러나요 확인해주세요"

**슬랙 메시지**:
> "🐛 로그인 버그 발견! 토큰 만료 시 리다이렉트 안 되고 에러 발생해요. 확인 부탁드려요~"

**Jira 설명**:
> "## 배경
> 토큰 만료 시 적절한 처리가 되지 않는 버그 발견
> 
> ## 현상
> - 토큰 만료 시 로그인 페이지로 리다이렉트되지 않음
> - 에러 화면만 표시됨
> 
> ## 기대 동작
> 토큰 만료 시 자동으로 로그인 페이지로 리다이렉트"

### 사용자 정의 채널

사용자는 기본 제공되는 채널 외에 **커스텀 채널**을 추가할 수 있습니다.
- 예: "Notion 페이지", "Discord 메시지", "LinkedIn 포스트"

## 다듬기 옵션

상황과 채널 외에 추가로 선택할 수 있는 세부 조정 옵션입니다.
결과물을 미세 조정하고 싶을 때 사용합니다.

| Option ID | 이름 | 효과 |
|-----------|------|------|
| `shorter` | 더 짧게 | 핵심만 남기고 불필요한 부분 제거 |
| `longer` | 더 자세하게 | 부연 설명과 맥락 추가 |
| `bullet` | 불릿으로 정리 | 나열된 내용을 불릿포인트로 구조화 |
| `formal` | 더 격식있게 | 톤을 높여 공식적으로 |
| `casual` | 더 캐주얼하게 | 톤을 낮춰 편하게 |
| `action-clear` | 액션 명확히 | 요청사항/다음 단계를 명확하게 |

### 옵션 사용 예시

**원문**: "회의 시간 조정해야 할 것 같아요 다들 시간 확인해주세요"

- **+ 더 짧게**: "회의 시간 조정 필요. 가능 시간 회신 부탁드려요"
- **+ 액션 명확히**: "회의 시간 조정이 필요합니다. 오늘 오후 6시까지 가능한 시간대를 회신해주세요."

## 사용자 플로우

```
1. 사용자가 텍스트 드래그하여 선택
2. Cmd+Shift+CC 입력
3. 다듬기 팝업 표시
   ├── 원문 표시
   ├── 상황 선택 드롭다운 (기본값: 마지막 사용한 상황)
   ├── 채널 선택 드롭다운 (기본값: 마지막 사용한 채널)
   ├── 추가 옵션 토글 (선택)
   └── 다듬은 결과 표시
4. 사용자가 결과 확인
   ├── [복사] → 클립보드에 복사, 팝업 유지
   ├── [바꾸기] → 원본 텍스트 대체, 팝업 닫힘
   ├── [다시 다듬기] → 동일 설정으로 재생성
   └── [ESC/외부 클릭] → 팝업 닫힘
```

## Requirements

### Functional Requirements

- **FR-P001**: 시스템은 전역 단축키 Cmd+Shift+CC를 감지하여 다듬기 팝업을 표시해야 함
- **FR-P002**: 시스템은 선택된 텍스트의 언어를 감지하고 같은 언어로 다듬어야 함
- **FR-P003**: 시스템은 Claude API를 사용하여 다듬기를 수행해야 함
- **FR-P004**: 다듬기 팝업은 원문과 다듬은 결과를 동시에 표시해야 함
- **FR-P005**: 사용자는 상황(Context)을 선택할 수 있어야 함
- **FR-P006**: 사용자는 채널(Channel)을 선택할 수 있어야 함
- **FR-P007**: 사용자는 추가 옵션(더 짧게, 더 명확하게 등)을 선택할 수 있어야 함
- **FR-P008**: 사용자는 "복사" 버튼을 통해 다듬어진 텍스트를 클립보드에 복사할 수 있어야 함
- **FR-P009**: 사용자는 "바꾸기" 버튼을 통해 원본 텍스트를 다듬어진 내용으로 대체할 수 있어야 함
- **FR-P010**: 사용자는 "다시 다듬기" 버튼을 통해 다른 결과를 생성할 수 있어야 함
- **FR-P011**: 시스템은 마지막으로 사용한 상황/채널 설정을 저장하고 기본값으로 사용해야 함
- **FR-P012**: 사용자는 커스텀 상황/채널을 추가할 수 있어야 함 (설정 화면에서)

### Non-Functional Requirements

- **NFR-P001**: 다듬기 결과는 3초 이내에 표시되어야 함 (500자 이하 기준)
- **NFR-P002**: 다듬기 팝업 UI는 번역 팝업과 일관된 디자인 언어를 사용해야 함

---

## Edge Cases

- 빈 텍스트를 선택하고 Cmd+Shift+CC를 누르면? → 에러 메시지 또는 무시
- 네트워크가 없는 상태에서 다듬기를 시도하면? → 네트워크 연결 필요 알림
- 매우 긴 텍스트(5,000자 이상)를 다듬으려고 하면? → 적절한 길이 제한 안내
- Claude API 키가 유효하지 않으면? → API 키 확인 필요 안내
- 이미 완벽한 글이라 다듬을 것이 없으면? → "이미 잘 작성된 글입니다" 메시지와 함께 원문 유지

## Key Entities

### PolishPreset (다듬기 프리셋)

```typescript
interface PolishPreset {
  id: string;
  context: ContextType | string;  // 기본 제공 또는 커스텀
  channel: ChannelType | string;  // 기본 제공 또는 커스텀
  options: PolishOption[];
  isDefault: boolean;
  createdAt: string;
}
```

  polishedText: string;
  context: string;
  channel: string;
  options: PolishOption[];
  language: Language;
  model: string;
  createdAt: string;
